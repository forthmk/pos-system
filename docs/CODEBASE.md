## 2. Golden rules

1. **The server decides money.** Screens send IDs and quantities; prices, discounts, VAT, totals and order numbers are calculated in the API (design §7.1). A total sent by a screen is never saved.
2. **Server data lives in TanStack Query.** No `useState` + `useEffect` fetching, no Redux for server data (CLAUDE.md rule 1).
3. **Backend first:** migration → API module → shared model/api → hook → UI (CLAUDE.md rule 2).
4. **Never delete sales history.** Orders are cancelled / voided; menu items, users and discounts are switched off with `is_active = 0`.
5. **Hide, don't delete, in the UI.** When a screen element must go, hide it behind a named flag (`const SHOW_X = false`) and keep the code — same rule as the commissary.
6. **Copy, don't import, from the commissary.** It is a reference only. Copy the file into this repo, adapt it, and never edit the commissary while working here.
7. **One ticket = one branch = one PR** (CLAUDE.md rule 3). Touching an unrelated shared file? Stop and ask first (rule 4).

### 3.2 Adding a migration

```
apps/api/src/migrations/YYYYMMDD_<letter>_<what>.ts      e.g. 20261202_a_add_orders_note.ts
```

```ts
import { Kysely, sql } from 'kysely';

// WHY this shape: cascade choices, uniqueness, what it mirrors. This comment is
// the only place that reasoning is recorded.
export async function up(db: Kysely<any>) {
    await sql`ALTER TABLE \`orders\` ADD COLUMN \`note\` varchar(255) DEFAULT NULL AFTER \`table_no\``.execute(db);
}

export async function down(db: Kysely<any>) {
    await sql`ALTER TABLE \`orders\` DROP COLUMN \`note\``.execute(db);
}
```

Rules (same as the commissary's `db-migration` skill):

- Raw `sql` DDL, backtick-quoted, `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci`.
- A named `KEY` **and** a named `CONSTRAINT` for every foreign key; pick the delete rule on purpose — history = `RESTRICT`, pure child rows = `CASCADE`, optional pointer = `SET NULL`.
- `down()` is the exact inverse of `up()`; drop children before parents.
- **Never edit a migration that has run anywhere.** Write a new one.
- Filenames sort = run order. Never rename one that has run.
- Runners live in `src/scripts/`, **not** in `src/migrations/` (the commissary keeps them beside the migrations, so Kysely imports — and runs — the runner itself; we don't repeat that bug).
- Kysely 0.29: `Migrator` / `FileMigrationProvider` come from `kysely/migration`.

### 3.3 Running

```bash
pnpm db:migrate        # apply pending   (apps/api: tsx src/scripts/migrate.ts)
pnpm db:rollback       # undo the LAST migration only
pnpm db:gen            # regenerate src/config/database/types.gen.ts — after EVERY migration
pnpm db:seed           # demo data; only runs on an empty database
```

`db:gen` reads `DATABASE_URL` from `apps/api/.env`. Never hand-edit `types.gen.ts` — if a type is wrong, the migration is wrong.

### 3.4 Seed data

`src/scripts/seed.ts` creates store `01` (QuickBite #01), terminals `KIOSK-01` / `POS-01` / `EXPO-01`, the four roles' users (dev logins are listed at the top of the file), every default setting (design appendix), the five discount types in the register's button order, and the menu from the UI references with en / zh / ko names. Prices match the mock-ups (3× Double Smash Burger + 2× Sundae = ₱595).

## 4. API (`apps/api`)

### 4.1 Module = 5 files

Same layering as the commissary (`modules/suppliers/` there is the cleanest template):

```
src/modules/menu/
  menu.routes.ts       endpoints + preHandler (auth / permission)
  menu.controller.ts   read params/body → call service → sendResult(reply, data)
  menu.service.ts      business rules; throws ApiError(msg, status, field)
```

Register it by adding `'menu'` to `routes` in `src/app.ts` → mounted at `/api/menu`. That array is the only registry.

## 5. Shared package (`packages/shared`)

| Folder | Holds | Used by |
|---|---|---|
| `model/` | TypeBox schemas + `Static<>` types (`PaginationSchema`, `MenuItem`, `Order`…) | api (via `dist`) and web (source) |
| `utils/` | pure helpers: `StrictObject`, pricing, slip code | api (via `dist`) and web (source) |
| `api/` | endpoint definitions per module: `menuApi(client).list()` | web |
| `axios/` | `createApi()` — base URL from `VITE_API_URL`, JWT from localStorage | web |

- After editing `model/` or `utils/`: `pnpm --filter @pos-system/shared build` (the api reads `dist/`).
- A new top-level folder must be wired in **three places**: `packages/shared/package.json` `exports`, `apps/web/vite.config.ts` alias, `apps/web/tsconfig.json` paths.

### 6.5 How to copy a component

1. Copy the file to the same path under `apps/web/src/`.
2. Fix imports (`@shared/model` types, `../../services/api`).
3. Remove commissary-only props / branches; keep the header comment and update it.
4. If it fetches data itself, move the fetch into a `hooks/api` hook — shared components take data and callbacks as props.
5. Note it in the ticket's “What was built”.

### 6.6 Conventions (same as the commissary)

- Form modals: one component for create + edit (`formData` undefined = create); name new ones `<Thing>FormModal.tsx`; re-seed local state in a `useEffect` on `isOpen` / `formData?.id`.
- Tables are server-paged and server-sorted; never sort a full array in the browser.
- Searches: suggestion lists show 4 rows and scroll; names only.
- Icons: `lucide-react` first, FontAwesome if needed.
- Toasts: `@pikoloo/darwin-ui`.

## 8. Local setup

```bash
npx -y pnpm@11.5.0 install                       # corepack's global pnpm is broken on this Mac
cp apps/api/.env.example apps/api/.env           # fill MYSQL_PASSWORD + DATABASE_URL
# create the database once (MySQL 8):  CREATE DATABASE pos_system CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;

npx -y pnpm@11.5.0 db:gen

```

The API runs on **3000** so it can run next to the commissary API (4000).
